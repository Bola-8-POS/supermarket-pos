`es-MX`, but the CI-critical suite's E2E fixture accounts default to `en-US`
(`scripts/lib/ensure-staff-account.ts`) — so the English-only text selectors in every cited
`e2e/**/*.spec.ts` reference file will NOT match once `seedStaffLocale()` puts the acting staff into

unique to one of these three domains, look up its real es-MX/en-US values in
`src/shared/lib/i18n/locales/{es-MX,en-US}/*.json` (grep the component for its `t('namespace.key')`
call) and build a dual-locale regex inline, mirroring `e2e/helpers/auth.ts`'s `WHO_ARE_YOU_RE`/
`LOGOUT_RE` convention (`/^(english|spanish)$/i`) — never copy an English-only regex from a cited CI
spec verbatim. Prefer an existing `data-testid` (locale-independent) wherever the cited spec already
provides one.

No one-way-door decisions (REVERSIBILITY_GATES): purely additive spec files reusing an already-proven
harness.
