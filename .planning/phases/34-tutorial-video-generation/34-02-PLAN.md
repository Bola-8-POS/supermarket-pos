<objective>
Stamp out the three domain tutorial videos (inventory, suppliers, payments) using the exact harness
proven by Plan 34-01's tracer — no new harness/config/conversion code in this plan, only new domain
spec files that import the already-proven `fixtures.ts`/`locale.ts`.

Purpose: expand VIDEO-02 coverage using the pattern that Plan 34-01 already validated end-to-end.
Output: three new spec files, each producing 2-3 `.webm` recordings (one workflow + 1-2 edge cases)
when run against `playwright.tutorial.config.ts`.

LOCALE SAFETY (carried over from 34-01, do not skip): this harness's default `TUTORIAL_LOCALE` is
`es-MX`, but the CI-critical suite's E2E fixture accounts default to `en-US`
(`scripts/lib/ensure-staff-account.ts`) — so the English-only text selectors in every cited
`e2e/**/*.spec.ts` reference file will NOT match once `seedStaffLocale()` puts the acting staff into
`es-MX`. Reuse the dual-locale constants already exported from `e2e/tutorials/i18n-selectors.ts`
(34-01) for cross-domain strings (checkout tile, process payment, done, etc.); for a string unique to
one of these three domains, look up its real es-MX/en-US values in
`src/shared/lib/i18n/locales/{es-MX,en-US}/*.json` (grep the component for its `t('namespace.key')`
call to find the exact key) and build a dual-locale regex inline, mirroring `e2e/helpers/auth.ts`'s
`WHO_ARE_YOU_RE`/`LOGOUT_RE` convention (`/^(english|spanish)$/i`) — never copy an English-only regex
from a cited CI spec verbatim. Prefer an existing `data-testid` (locale-independent) wherever the
cited spec already provides one.

No one-way-door decisions (REVERSIBILITY_GATES): purely additive spec files reusing an already-proven
harness; nothing here touches app code, schema, or the CI-critical suite.
</objective>
