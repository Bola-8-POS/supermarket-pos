<objective>
Close UAT gap G-34-1: tutorial videos are "too fast to follow" because `narrate()` (`e2e/tutorials/fixtures.ts`) only
pauses AFTER a whole action closure finishes — the 2-3 raw `.click()`/`.fill()` calls bundled inside a single
`narrate()` block in every domain spec fire back-to-back with zero delay, and `playwright.tutorial.config.ts` sets
no `launchOptions.slowMo` to pace them. Fix: add Playwright's native `slowMo` primitive (one-line config change),
prove it measurably paces individual actions before committing to the expensive full run, then regenerate the
entire 50-file bilingual `tutorial-videos/` deliverable with corrected pacing.

Purpose: the phase's actual UAT-facing deliverable (customer training videos) is unusable until every recorded
click/fill is individually visible, not just the pauses between narrate() blocks.
Output: `playwright.tutorial.config.ts` with `slowMo` set; all 50 `tutorial-videos/*.mp4` files regenerated with
per-action pacing.
</objective>

<task type="auto">
  <name>Task 1: Add native per-action pacing via launchOptions.slowMo</name>
  <files>playwright.tutorial.config.ts</files>
  <action>
    In `playwright.tutorial.config.ts`'s `use` block, add a `launchOptions: { slowMo: 600 }` entry
    alongside the existing `headless`/`viewport`/`video` keys. This is Playwright's own built-in
    per-operation pacing primitive (root cause per UAT gap G-34-1: it was never set, so every raw
    `.click()`/`.fill()` inside a single `narrate()` closure — e.g. `checkout.spec.ts`'s "Search for a
    product and add it to the cart" block, which fills the search box then clicks the product result
    with zero gap — fired back-to-back). 600ms is the starting value per the diagnosed fix direction's
    500-700ms range: enough that two bundled actions (fill + click) are clearly separated on playback,
    not so long it makes an already-long full-walkthrough recording (94s at 34-06) balloon
    unreasonably. Do not touch `e2e/tutorials/fixtures.ts` or any `*.spec.ts` file in this task — the
    whole point of `slowMo` is that it paces every existing action call with a single config line, no
    spec-file changes needed. Add a one-line comment above the new key explaining why (mirrors this
    file's existing comment style), referencing that it fixes intra-narrate()-block pacing that
    `pacing.ts`'s `resolveHoldMs` only ever applied between blocks.
  </action>
  <verify>
    <automated>node -e "const c=require('fs').readFileSync('playwright.tutorial.config.ts','utf8'); if(!/launchOptions:\s*\{[^}]*slowMo:\s*\d+/s.test(c)){console.error('FAIL: launchOptions.slowMo not found in use block'); process.exit(1);} console.log('PASS: slowMo configured');"</automated>
  </verify>
  <done>`playwright.tutorial.config.ts`'s `use.launchOptions.slowMo` is set to a numeric millisecond value; no other file changed.</done>
</task>
